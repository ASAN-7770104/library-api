# Library Book Management REST API

**Name:** Assanali Tursumbayev  
**Group:** Tursumbayev Assanali A2  
**Course:** VR 113153 Web Development II, Homework Assignment 2

A small RESTful API for a library, built with **Node.js** and **Express.js**. A client can create, read, update and delete books, and filter and sort the list with query parameters. There is no front end: every endpoint is tested with Postman or Thunder Client.

Books are stored in `data/books.json` and read/written with the native `fs/promises` module, so the data survives a restart.

## Requirements

- Node.js 18 or newer
- npm

## Install and run

```bash
npm install
npm start
```

The server runs on <http://localhost:3000>. To use another port, set `PORT` (for example `PORT=4000 npm start`; on Windows PowerShell: `$env:PORT=4000; npm start`).

For development with automatic restart (nodemon):

```bash
npm run dev
```

## Data model

| Field | Type | Rules |
|---|---|---|
| `id` | string | Generated by the server (`crypto.randomUUID()`), unique |
| `title` | string | Required, 2 to 100 characters |
| `author` | string | Required, 2 to 60 characters |
| `year` | number | Required, a whole number between 1450 and the current year |
| `genre` | string | Required, for example `"Fiction"`, `"Science"`, `"History"` |
| `available` | boolean | Optional, defaults to `true` |
| `createdAt` | string | ISO date, set by the server |

`id` and `createdAt` are always created by the server: if a client sends them, they are ignored.

## Response format

Every response uses the same JSON shape.

```json
{ "success": true, "data": "..." }
```

```json
{ "success": false, "error": "Book not found" }
```

```json
{ "success": false, "errors": ["title is required", "genre is required"] }
```

`DELETE` answers with `204 No Content` and no body.

## Endpoints

| Method | Route | Purpose | Success status |
|---|---|---|---|
| GET | `/api/books` | Return all books (supports filtering and sorting) | 200 |
| GET | `/api/books/stats` | Bonus: total, available and count per genre | 200 |
| GET | `/api/books/:id` | Return one book by id | 200 |
| POST | `/api/books` | Create a new book | 201 |
| PUT | `/api/books/:id` | Replace **all** fields of a book | 200 |
| PATCH | `/api/books/:id` | Update **only** the fields that are sent (for example `available`) | 200 |
| DELETE | `/api/books/:id` | Delete a book | 204 |

### Filtering and sorting on `GET /api/books`

| Parameter | Meaning |
|---|---|
| `?genre=Fiction` | Only books of this genre (case-insensitive) |
| `?author=Abai` | Books whose author contains the text (case-insensitive) |
| `?available=true` | Only available books (`true` or `false`) |
| `?sort=year` / `?sort=-year` | Sort by year, ascending / descending |
| `?sort=title` / `?sort=-title` | Sort alphabetically by title, ascending / descending |

Parameters can be combined, for example `/api/books?genre=History&sort=-year`. An invalid value (`?sort=banana`, `?available=maybe`) returns `400`.

**400 Bad Request** (validation): `POST /api/books` with `{"title":"A","author":"Andrew Hunt","year":1200}`

```json

  "errors": [
    "title must be between 2 and 100 characters",
    "genre is required",
```

**400 Bad Request** (invalid query): `GET /api/books?sort=banana`

```json
{
  "success": false,
  "errors": ["sort must be one of: year, -year, title, -title"]
```


## Middleware (all written by me, no ready-made packages)

| File | What it does |
|---|---|
| `middleware/logger.js` | For every request prints the method, URL, status code and response time, for example `GET /api/books 200 - 4 ms` |
| `middleware/validateBook.js` | Checks the body of `POST` and `PUT` against the data-model rules and returns `400` with a list of errors. A second function checks `PATCH` (only the fields that are sent) |
| `middleware/notFound.js` | Returns `404` in JSON for an unknown route and for an id that does not exist |
| `middleware/errorHandler.js` | The single error handler `(err, req, res, next)`: returns `500` in JSON (or `400` for a broken JSON body) and never lets the server crash |

## Status codes used

| Code | When |
|---|---|
| 200 | Successful GET, PUT, PATCH |
| 201 | Book created (POST) |
| 204 | Book deleted (DELETE), no body |
| 400 | Invalid body or invalid query parameter |
| 404 | Unknown route or unknown book id |
| 500 | Unexpected server error (for example a damaged `books.json`) |

## Testing with Postman or Thunder Client

1. Start the server with `npm start`.
2. Import `Library_API.postman_collection.json` (Postman: **Import**; Thunder Client: **Collections → Import**).
3. The collection has one saved request per endpoint, including a `400` and a `404` case. It uses the variables `baseUrl` (`http://localhost:3000`), `sampleId` (a book from `books.json`) and `createdId` (copy the `id` from the response of the POST request).
4. `Screenshots.pdf` shows every endpoint with the request, the response body and the status code, and the logger output in the terminal.

To see the `500` answer: stop the server, put broken text in `data/books.json`, start the server and call `GET /api/books`. The server answers `500` and keeps running. Restore the file afterwards.
